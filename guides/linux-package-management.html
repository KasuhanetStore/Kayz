A Practical Guide to APT Package Management on Debian and Ubuntu

KasuhaNET Resources · Technical guide · Updated 12 November 2026

APT is the standard package-management tool on Debian-based systems. This guide covers a safe, repeatable workflow for refreshing package information, installing software and checking the result.

Before you begin

These commands are intended for Debian and Ubuntu systems. You need an account with sudo privileges. Package names and availability can differ between releases.

1. Confirm the operating system

Check the distribution and release before following instructions written for a particular system:

cat /etc/os-release

Look at the ID and VERSION_ID values. If you are using a different Linux family, its package manager may not be APT.

2. Refresh the package index

sudo apt update

This downloads the latest package metadata from the repositories configured on the machine. It does not upgrade installed applications by itself. Read the output and investigate repository or signature errors rather than ignoring them.

3. Install a package

For example, to install the curl command-line tool:

sudo apt install curl

APT displays the packages and disk space involved and asks for confirmation. Review the proposed changes before accepting them, especially on production servers.

4. Verify the installation

curl --version
apt policy curl

The first command prints the installed program version. The second shows package status and repository information.

5. Find a package or inspect details

apt search package-name
apt show package-name

Replace package-name with the software you are looking for. Search results can include similarly named packages, so check the description and source before installing.

6. Upgrade carefully

sudo apt upgrade

Review the list of packages to be upgraded before confirming. For remote or production systems, take an appropriate backup and ensure you have a recovery route before making broad system changes.

Common problems

  • Package not found: run sudo apt update, check spelling and confirm that the correct repository is enabled for your release.
  • Lock is held: another package process may be running. Wait for it to finish; do not delete lock files while package tools are active.
  • Repository or signature error: check the repository URL, system clock and signing-key instructions from the repository's official documentation.

Safety checklist

  • Use repositories you trust and understand.
  • Read proposed package changes before confirming.
  • Avoid piping remote scripts directly into a shell unless you have reviewed and trust the source.
  • Keep backups for important servers and schedule maintenance for disruptive upgrades.

APT documentation is available through the Debian and Ubuntu manuals. This guide is educational; always check the documentation for your distribution version.
