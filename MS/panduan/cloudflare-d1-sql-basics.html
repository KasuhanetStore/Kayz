Cloudflare D1: Semak Jadual dan Jalankan Pertanyaan SQL dengan Selamat

KasuhaNET Resources · Panduan teknikal · Dikemas kini 12 November 2026

Cloudflare D1 ialah pangkalan data SQL tanpa pelayan yang dibina berasaskan SQLite. Langkah pertama ketika menyelenggara projek sedia ada ialah memeriksa struktur pangkalan data dan memahami rekod sebelum membuat perubahan.

Penting

Gunakan nama pangkalan data yang tertera dalam konfigurasi atau dashboard Cloudflare. Nama binding Worker seperti DB ialah pemboleh ubah pada peringkat kod dan tidak semestinya nama sebenar pangkalan data D1.

1. Senaraikan pangkalan data D1

Dengan Wrangler dipasang dan telah disahkan ke akaun Cloudflare yang betul, jalankan:

npx wrangler d1 list

Kenal pasti pangkalan data yang digunakan oleh projek. Semak konfigurasi Wrangler dan persekitaran deployment sebelum menjalankan arahan jauh.

2. Semak senarai jadual

Gantikan NAMA_DATABASE_ANDA dengan nama tepat daripada arahan sebelumnya:

npx wrangler d1 execute NAMA_DATABASE_ANDA --remote --command "SELECT name FROM sqlite_master WHERE type = 'table' ORDER BY name;"

Pertanyaan ini membaca metadata skema SQLite dan menyenaraikan jadual. Ia tidak mengubah rekod.

3. Semak lajur jadual

npx wrangler d1 execute NAMA_DATABASE_ANDA --remote --command "PRAGMA table_info('stripe_orders');"

Gantikan stripe_orders dengan jadual yang ingin diperiksa. Hasilnya menerangkan nama lajur, jenis data, kebolehan menerima NULL, nilai lalai dan maklumat primary key.

4. Baca sampel kecil

npx wrangler d1 execute NAMA_DATABASE_ANDA --remote --command "SELECT id, status, created_at FROM stripe_orders ORDER BY created_at DESC LIMIT 10;"

Pilih lajur yang diperlukan sahaja dan gunakan had rekod yang kecil. Elakkan memaparkan nama pelanggan, alamat e-mel, nombor telefon atau data peribadi dalam log awam dan tangkap layar.

5. Gunakan pertanyaan berparameter dalam Workers

Apabila input aplikasi digunakan, ikat nilai parameter dan bukannya mencantumkannya terus ke dalam rentetan SQL:

const result = await env.DB.prepare(
  "SELECT id, status FROM stripe_orders WHERE id = ?"
).bind(orderId).first();

Parameter binding membantu mencegah SQL injection dan memisahkan nilai data daripada sintaks SQL. Nama jadual dan lajur biasanya tidak boleh dibekalkan sebagai nilai parameter biasa; pilihnya melalui logik aplikasi tetap yang dipercayai.

6. Sandarkan data dan ubah skema dengan cermat

Sebelum migrasi atau pertanyaan yang memadam data, sahkan pangkalan data dan persekitaran sasaran, buat sandaran menggunakan kaedah Cloudflare yang disokong semasa, dan uji migrasi pada salinan bukan produksi jika boleh. Semak setiap arahan UPDATE atau DELETE supaya mempunyai klausa WHERE yang betul. Jangan jalankan arahan pemusnah semata-mata untuk melihat kesannya.

Semakan berguna

  • Sahkan akaun Cloudflare dan pangkalan data yang betul sebelum menggunakan --remote.
  • Bezakan nama pangkalan data produksi dan pembangunan dengan jelas.
  • Gunakan migrasi yang dijejak dalam version control untuk perubahan skema yang boleh diulang.
  • Jangan simpan kelayakan pangkalan data dan token API dalam fail sumber.
